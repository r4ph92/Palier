# 033 — Occupation en direct et écart du compteur

**Contexte.** #71 : Sophie Lavoie voit, par niveau, les places par état à côté du compteur de véhicules et de l'écart entre les deux (Q35). Un parking à population mixte (abonnés et Palier) a des places individuelles floues ; l'écart dit combien de places demandent une vérification à pied.

**Décision.**
- **Calcul à la lecture, pas de tâche `reconcile_counts`.** Q35 prévoyait une tâche chaque minute qui compare le compteur aux places occupées et affiche l'écart tel quel. L'écart est une soustraction de deux valeurs déjà en base : la calculer à chaque lecture donne le même chiffre sans retard et sans table ni verrou de plus. La tâche est donc supprimée du modèle ; le tableau de bord relit toutes les 30 s, ce qui tient la contrainte « moins de 60 s ».
- **Une route** `GET /v1/dashboard/lots/:id/occupancy` → `{ lotId, lotName, vehicleCount, levels: [{ code, counts }], occupiedOrAssignedCount, counterGap: { kind, spots } }`. Le parking d'un autre opérateur, un id inconnu et un id mal formé répondent le même `LOT_NOT_FOUND` 404 : la lecture SQL nomme l'opérateur du membre (comme `LotSetupRepository`).
- **Une seule instruction SQL** (`PostgresLevelOccupancyReader`) : niveaux du parking (même sans place, dans l'ordre d'affichage), places groupées par état, compteur et nom. Une instruction est un instantané : niveaux, places et compteur concordent sans verrou du parking. Les états absents d'un niveau valent 0.
- **Places occupées ou attribuées** = `OCCUPIED` + `OCCUPIED_UNKNOWN` + `ASSIGNED` dont la session est `ENTRY_CONFIRMED` (fragment `confirmedAssignedSpotOf`). Une place `ASSIGNED` dont la boucle n'a pas fermé (session `CREATED`) n'est pas comptée : le véhicule n'est peut-être pas entré, donc le compteur ne l'a pas encore vu. Le tableau par niveau, lui, montre toutes les places `ASSIGNED`. `HELD` et `OUT_OF_SERVICE` ne sont pas comptées.
- **Écart** (`computeCounterGap`) : compteur ≥ places prises → `SPOTS_TO_CHECK`, de `compteur − places` places (0 compris) ; compteur plus bas → `COUNTER_BELOW`, de `places − compteur`. Le compteur ne se corrige pas : l'écart est affiché tel quel.
- **Tableau de bord** : `/lots/:id/occupancy`, lien « Occupation » depuis la page du parking. Relecture toutes les 30 s (`usePolledResource`) sans état de chargement entre deux lectures. Une lecture qui échoue garde les derniers chiffres et affiche une note discrète (`role="status"`) tant qu'une lecture n'a pas réussi ; un premier chargement qui échoue montre l'erreur et « Réessayer ». Une 401 relit la session comme partout.
- **`SPOT_STATES`** passe dans `packages/shared-types` (`spotStates`) : l'API le réexporte, le tableau de bord en tire l'ordre et les libellés. L'enum Postgres ne change pas (`db:generate` ne produit aucun écart).

**Conséquences.** `reconcile_counts` disparaît du tableau des tâches planifiées de `docs/02-modele-de-donnees.html`, du planificateur de `docs/04-architecture.html` (cinq transitions), du dossier complet et de `tools/build4.py` ; `DECISIONS.md` garde Q35 telle que décidée, avec une note qui renvoie ici. Un parking très chargé relit trois jointures toutes les 30 s par onglet ouvert ; les index `level_lot_id_code_unique`, `aisle_level_id_lot_id_index`, `spot_aisle_id_lot_id_index` et `parking_session_one_active_per_spot_index` servent les jointures, et la taille d'un parking le permet, à mesurer si un parking dépasse quelques milliers de places. L'étiquette « attribuée » du tableau peut surprendre : une place `ASSIGNED` sans boucle fermée y figure mais n'entre pas dans les places occupées ou attribuées.

**Preuve SQL.** Le SQL n'est prouvé que sur la base de la voie (002, 005) ; les instructions ont des tests sur un exécuteur scripté. Scénario joué à la main sur `palier_l71` (transaction annulée ensuite), avec le vrai lecteur : Parking Démo, 3 `OCCUPIED`, 2 `ASSIGNED` (une session `ENTRY_CONFIRMED`, une `CREATED`), 1 `HELD`, 1 `OCCUPIED_UNKNOWN`, 1 `OUT_OF_SERVICE`, 2 `AVAILABLE`, compteur 7 → niveau P1 `{ AVAILABLE: 2, HELD: 1, ASSIGNED: 2, OCCUPIED: 3, OCCUPIED_UNKNOWN: 1, OUT_OF_SERVICE: 1 }`, 5 places occupées ou attribuées, écart `SPOTS_TO_CHECK` de 2 ; Pierre Roy sur ce parking : `LOT_NOT_FOUND`. Le script `npm run test:db` de CLAUDE.md n'existe pas dans cette branche.
