# 049 — Connexion avec Apple ou Google, et build de développement

**Contexte.** #30 : le conducteur crée son compte et se connecte avec Apple ou Google, sans mot de passe Palier. Les deux connexions passent par des modules natifs (`expo-apple-authentication`, `@react-native-google-signin/google-signin`). Expo Go ne contient pas le module Google, et son Apple signe pour `host.exp.Exponent`, une audience que l'API refuse. La décision 001 prévoyait Expo Go « tant qu'aucun module natif n'existe » : cette condition tombe.

**Options.**
- **Rester dans Expo Go et n'essayer les connexions que dans TestFlight.** Chaque essai coûte un build de production, et le développement quotidien ne passe jamais par le vrai écran de connexion.
- **Build de développement `expo-dev-client` (retenue).** Un build EAS du profil `development` (simulateur iOS) contient les modules natifs, et Metro y recharge le JavaScript comme dans Expo Go.

**Décision.**
- **App.** `expo-dev-client` remplace Expo Go (remplace la ligne « Expo Go » de 001). Profil `development` dans `apps/mobile/eas.json` (`developmentClient`, `ios.simulator`). Après tout ajout de module natif ou de plugin dans `app.config.ts`, il faut refaire ce build.
- **Jeton vérifié par l'API.** L'app envoie le jeton d'identité du fournisseur à `POST /v1/sign-in/apple` ou `/v1/sign-in/google`. L'API le vérifie avec `jose` contre les clés publiques du fournisseur (JWKS distant) : signature RS256, émetteur, audience (`APPLE_BUNDLE_ID`, `GOOGLE_IOS_CLIENT_ID`), expiration, et `email_verified`. Un jeton refusé donne 401 sans compte ni session. Un fournisseur sans audience configurée donne 503 `SIGN_IN_UNAVAILABLE`. Les deux routes partagent la limite de 10 connexions par minute et par adresse.
- **Identité liée au compte.** Table `user_identity (provider, subject, user_id)`, unique sur `(provider, subject)`. Le `sub` du fournisseur, jamais le courriel, retrouve le compte. Une première connexion crée l'utilisateur avec le courriel vérifié (y compris un courriel relais « Masquer mon adresse »), ou rejoint le compte qui a déjà ce courriel. Le même courriel vérifié chez Apple et chez Google ouvre donc le même compte. Après le pentest, la jonction est resserrée :
  - elle n'a lieu que si le fournisseur possède la boîte du courriel : Apple toujours, Google pour Gmail et pour les domaines qu'il gère (revendication `hd`). Sinon, quiconque a fait vérifier chez Google une adresse qu'il n'a plus prendrait le compte ;
  - elle n'a jamais lieu vers le compte d'un opérateur (ligne dans `operator_member`), qui ne se connecte qu'au tableau de bord ;
  - dans ces deux cas, rien n'est écrit et l'API répond 409 `ACCOUNT_NOT_LINKABLE` ; l'app dit de se connecter comme lors de la création du compte ;
  - le courriel n'est mis en minuscules que de A à Z : une minuscule Unicode complète ramène des sosies (le signe kelvin devient « k ») sur le courriel d'une autre personne. Une seule transaction, avec `on conflict do nothing` sur le courriel et sur l'identité, et une relecture finale : deux premières connexions simultanées finissent sur le même compte.
- **Nom.** Le nom donné par le fournisseur nomme le nouveau compte, puis celui qu'Apple remet à l'app à la première connexion seulement. Sans nom, le compte est créé avec un prénom vide, et l'app demande le nom (`PUT /v1/me/name`, consentement exigé) **après** l'avis de confidentialité, puisque le nom est un renseignement personnel.
- **Client Google.** L'identifiant du client iOS est public (il est dans chaque build) : `apps/mobile/src/auth/googleClient.ts`, et son schéma inversé dans `app.config.ts` (un test vérifie qu'ils correspondent).

**Conséquences.** `npm run ios` ouvre le build de développement au lieu d'Expo Go : il faut l'installer une fois dans le simulateur. L'App ID `ca.palier.app` doit avoir la capacité « Sign in with Apple ». La connexion de test reste dans les bundles de développement. La vérification réelle d'un jeton Apple ou Google ne se prouve que dans le build de développement ou dans TestFlight (décision 002) ; les tests unitaires signent leurs propres jetons avec une clé locale. Hors de cette décision : la révocation d'un compte Apple (notification serveur à serveur), la suppression du compte, et un nonce lié à chaque demande : un jeton d'identité volé peut ouvrir des sessions jusqu'à son expiration (environ 10 minutes chez Apple, 1 heure chez Google).
